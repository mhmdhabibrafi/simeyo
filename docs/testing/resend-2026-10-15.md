An initial run had six Firebase fixture failures because Windows OpenSSL could not generate keys; rerunning with the existing XAMPP OpenSSL configuration passed. Application credentials and database were not changed.
- Direct Resend HTTPS send from the configured domain to `delivered@resend.dev`: HTTP 200 with an accepted message ID. A fixed idempotency key avoided duplicate provider probes.

A non-persisted synthetic model with ID zero was used; no account was created, password reset token stored, or production user notified. Signed links and credentials were not printed or committed.

- Public browser: availability reports delivery enabled; recovery button enabled; no obsolete unavailable notice; 390px light/dark views fit; zero page errors. Missing-CSRF recovery request returns 419. No production account was created or modified.
- [Redacted public results](results/resend-public-2026-10-15.json) and fresh recovery screenshots were retained and visually inspected. Implementation follows [Laravel's Resend driver](https://laravel.com/framework/docs/12.x/mail#resend-driver); simulator scope follows [Resend test addresses](https://resend.com/docs/dashboard/emails/send-test-emails).
- Internal trusted TLS/security/health checks and real WSS handshake passed after restart. Queue probe passed with zero ready/failed jobs. Existing PostgreSQL/media volumes, keys and user data were preserved.
