# Photo viewer refinement, 2026-10-16

The web photo viewer now keeps all attachments accessible within one dialog, with previous/next controls, a position indicator, bounded keyboard navigation and a wider desktop image area. Mobile controls use icons with accessible names. Images retain their proportions and private media URLs remain unchanged.

Regression testing caught missing keyboard focus restoration when closing a dialog opened without a Radix trigger. The shared dialog now remembers the focused opener and restores it if it remains connected. Existing modal focus trapping and Escape handling remain with Radix.

Web lint and production build passed. The first 20-case presentation run passed 19 cases and failed the new focus-restoration assertion. That failure led to the shared fix; final regression results and deployment are recorded below when verified. These browser cases use fictional API fixtures, not production accounts. Physical-device and native photo-viewer acceptance are outside this change.

Final local regression: **20 presentation cases passed (1.0 minute)**, including six-image viewing, previous/next keyboard navigation, disabled boundary actions, Escape and focus restoration, 320px dark-theme dialog overflow and WCAG AA checks. The fresh 390px viewer screenshot was visually inspected. Existing posting failure/retry, partial upload recovery, settings, messages and composer flows passed in the same run. No API, database or native source changed.
