# Daily use and mobile profile improvements, 2026-10-17

Implementation and acceptance in progress. Application source and deployment results will be recorded after verification.

## Scope

Home post menus hide stories and reduce the author's score to 25 percent in NEW For You snapshots. Preferences persist per account in PostgreSQL; direct threads/bookmarks/profile access is unaffected. Hidden posts are rechecked while paging frozen snapshots. Settings provides counts and a confirmed reset. This is an explicit author preference, not semantic topic inference.

Link cards display the first HTTP(S) URL's domain/path. No external page, image, favicon or metadata fetch occurs in either browser or API. These are address previews, not fetched editorial titles or Open Graph thumbnails.

Follower/following pages now expose existing literal, cursor-paginated scoped search. Private profiles explain pending approval and route unauthorized count links to that explanation; the API still denies private relationship lists.

Typing state contains only a boolean in the shared cache, expires after six seconds and requires current participant/campus/block/send-policy authorization. The active chat polls every two seconds with background polling disabled; writes are limited to one per three seconds while typing, plus stopping on blur/inactivity/send/hidden/unmount. No draft text is transmitted. Inbox, navigation badges and read actions share an authorized database-derived total across ALL conversations; realtime invalidation and periodic refresh cover updates. This is ephemeral polling, not a new public presence channel.

Motion preference in Settings supports device/default or reduced motion, persists locally and always respects the OS reduced-motion preference. Mobile menu/action targets and toast dismissal use 44-pixel targets; active scale transitions are removed in reduced-motion mode. Axe/keyboard/mobile acceptance is recorded separately from physical-device testing.

The mobile editor has one sticky compact Save header, no competing mobile header/navigation, a permanent 3:1 banner area, separate avatar control and confirmation before removing photos. Text fields use 16-pixel fonts on mobile to avoid focus zoom. Avatar/cover crops open a scrollable bottom sheet on phones; cover uses the full available preview width. Photo save stays independent of text edits and failed photo uploads retain the crop. Banner/avatar removal is owner-only; failed storage writes do not update profile paths. Profile banners use the same 3:1 aspect ratio.

## Operational scope

Owner requested server-only storage. The maintenance script creates a new restricted timestamped backup directory, validates database/media archive inventories and hashes database/media/environment snapshot files. Failures retain a private .partial directory and never publish a completed manifest. No retention deletion is automated. This is a same-host backup, not off-host protection; archive inventory alone is not a production restore drill. Live database/media snapshots are sequential; no media deletion/versioning retention guarantee is claimed.

The five-minute monitor checks service processes, a web HTTP response, database/queue/worker heartbeat, disk reserve and backup freshness. API errors are counted without request paths, user IDs or message content in five minute buckets; five or more 5xx responses fail the application check. State is mode 0600. Changed failures/recovery are recorded in local system journal; systemd OnFailure also records an alarm. No external notification recipient/provider is configured, and no automatic repairs/data deletion occur. A host outage cannot alert from that same host.
