# Read receipts, installation offer and flexible galleries — 2026-10-16

Application source: **e4bbb57**. These changes extend existing messaging, notifications, PWA and media flows. No database migration or new dependency was needed.

## Behavior

- Outgoing chat messages display one check after API persistence and two when the recipient's stored read watermark reaches that message. This is server acceptance/read state, not proof of delivery to an offline device. Receipt updates broadcast private invalidation events without message content. Both web and native consume the additive `recipient_read_message_id` field, defaulting to zero with older APIs.
- Web chat acknowledges only the loaded incoming cursor when the tab is visible and the reader is near the bottom. Scrolling history does not acknowledge new unseen messages. Native uses focused/active-screen state and viewable incoming items. The API verifies the supplied message belongs to the authorized conversation and keeps read state monotonic. A retry control appears if acknowledgement fails.
- Opening Activity marks loaded unread IDs read in batches, preserving ownership and visibility checks and leaving future arrivals untouched. Hidden/background web tabs wait until visible. Native uses focus/foreground events. Failures retain unread state and expose retry controls.
- A non-blocking installation offer appears when the browser emits `beforeinstallprompt`, with Install, Later and Close actions. Postponement is remembered for the browser session. Standalone display mode suppresses the offer. Unsupported browsers retain the existing Settings installation guidance; no fake native prompt is presented.
- Removed the four-attachment quota from API, web and native selection. Removed the application 4 MB restriction for post/profile uploads. The release transport ceiling is **64 MB per file**, with a 68 MB request ceiling. JPEG/PNG/WebP validation, 4096px dimension protection, private media authorization and metadata-removing reencoding remain. This is not infinite server capacity. Native images continue to be resized before upload. Upload rate controls remain active; failed batches retain their existing retry flow.
- Composer previews have bounded scrolling; feed photos use a horizontal snap gallery rather than an ever-taller image grid. Page changes fade in, placeholders shimmer, loading text has a spinner and dialog/install/button interactions have short transitions. The existing reduced-motion setting disables animations/transitions.
