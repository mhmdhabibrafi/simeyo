## Rules and scope

Runtutan counts consecutive calendar days with a successful new story, image-only story, quote or reply. Time is fixed to Asia/Jakarta (WIB), with a 00:00 boundary. Multiple posts in one day add no extra days. Yesterday's streak remains current until today ends; missing a full day resets current count to zero, retaining the longest. The next qualifying post starts again at one.

Counts begin with the first new qualifying post after installation. Existing history is not backfilled. Reading/login, likes, repost interactions, editing, failed/rolled-back requests and retries of a previously accepted post do not add a day. Deleting a story does not erase its already completed day. There is no leaderboard, freeze purchase, push reminder or public activity-history display.

## Implementation

One user_streaks row per user, foreign key cascade on account deletion. Record runs inside the existing post transaction under its author row lock; concurrent requests serialize and uniqueness protects first insert. No client-supplied date or increment endpoint. GET /api/v1/me/streak is read-only, authenticated and approved-campus-only, returning current_days, longest_days, completed_today, timezone and next_reset_at. Shared Zod/OpenAPI types validate the response.

A compact monochrome profile section is shown only to the signed-in owner. It has loading, retry and empty/start states, and refreshes after successful posting plus a 60-second foreground poll (so midnight display can lag up to a minute). API counts remain authoritative. No native screen was added in this web/PWA update.
